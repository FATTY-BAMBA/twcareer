# Taiwan résumé and application conventions

Local judgment is the differentiator. A generic tool rewrites a Taiwanese résumé into an American one — one page, heavy quantification, no 自傳, no 期望待遇 — and it reads wrong to the person receiving it.

Each rule below carries a reason and a last-reviewed date. Update the module when norms change; do not scatter these facts into the skill body.

---

## 104 structured sections

Last reviewed: 2026-08

104 applications are not a Word file upload. Applicants build a structured profile inside 104, section by section, and the employer reads it in 104's own layout. Output must therefore be **paste-ready per section**, not one continuous document.

Sections that matter: 個人簡介 / 工作經歷 / 專長技能 / 專案成就 / 自傳 / 求職條件（含期望待遇）.

**Implication:** the hero output is the section pack. A Word or PDF résumé is the secondary artifact, for emailing HR directly or for 外商.

---

## 自傳

Last reviewed: 2026-08

Still expected in most local applications, and generic AI tools either omit it or produce something that reads like a translated cover letter.

A workable four-part shape:

1. 背景與人格特質 — brief, concrete, not 「我從小就對…充滿熱情」
2. 專業能力 — what they can actually do, tied to real experience
3. 相關經驗與成果 — the strongest one or two stories, not a list
4. 應徵動機與規劃 — why this company, what they intend to do there

Length: roughly 500–800 characters for most roles. Longer reads as padding.

**Bad opening, extremely common:** 「我出生於一個平凡的家庭…」 — Start with what they do and what they're good at.

**Rule:** the 自傳 is bound by the same evidence rules. It is prose, not a licence to invent.

## 期望待遇

Last reviewed: 2026-08

Applicants are commonly asked to state an expected salary, and it appears in 求職條件.

What to help with:
- Turning a number into a defensible range with reasoning
- Language for staying flexible without sounding evasive: 「希望在 X–Y 之間，實際可以再依職務內容與整體條件討論」
- Making clear that being invited to interview does not mean the figure is accepted — compensation is still settled through interviews and internal salary assessment

What **not** to do:
- Do not invent market salary data or cite figures the tool cannot source
- Do not pressure the user to disclose current pay
- If they want benchmarks, tell them plainly the tool doesn't have salary data and point them at public sources

## Employment types

Last reviewed: 2026-08

正職 / 約聘 / 派遣 / 兼職 / 實習 are materially different and must be stated accurately. Presenting 派遣 or 約聘 work as 正職 is a factual misstatement that surfaces in reference checks.

責任制 is worth capturing in the profile as a constraint, since it often drives the search.

---

## Compensation vocabulary

Last reviewed: 2026-08

月薪 vs 年薪 vs 月數 (13 個月、14 個月) vs 年終 vs 分紅 vs 三節獎金. A stated "annual" figure is ambiguous without knowing how many months it assumes. When the user gives a compensation figure, record which basis it is on — otherwise every later negotiation is built on a number nobody can interpret.

---

## 外商 vs 本土

Last reviewed: 2026-08

Different registers, and the same résumé should not be sent to both unchanged.

| | 本土 | 外商 |
|---|---|---|
| 自傳 | expected | often replaced by a cover letter |
| Length | more detail tolerated | tighter, more quantified |
| Language | 中文 | often English, or bilingual |
| Tone | 穩重、具體 | direct, achievement-forward |

Detect which from the JD's language and phrasing, and say which register was chosen.

---

## One page?

Last reviewed: 2026-08

The US one-page convention does not transfer. Local applications tolerate more detail, particularly in 自傳 and 工作經歷. Do not cut real content to hit a foreign page target.

---

## Photographs and personal data

Last reviewed: 2026-08

Some templates still request a photo, 身分證字號, marital status, or family details. This tool does not store or generate those fields. If a form demands one, tell the user it's their call to fill in directly, and explain that the tool keeps that data out by design.
